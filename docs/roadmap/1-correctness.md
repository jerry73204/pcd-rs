# Phase 1: Correctness

Fix interop-breaking bugs and missing format support that prevent pcd-rs from
correctly reading files produced by other implementations.

## 1.1 Fix binary_compressed SoA layout

The binary_compressed format uses column-major (SoA) storage: all values for
field 0, then all values for field 1, etc. pcd-rs currently reads and writes
in row-major (AoS) order, making it incompatible with PCL and every other
implementation.

- [x] Reader: after LZF decompression, transpose column-major data into
      row-major before feeding to `read_chunk`
- [x] Writer: transpose row-major buffered data into column-major before
      LZF compression
- [ ] Add a PCL-generated binary_compressed fixture to `test_files/`
- [x] Test round-trip: write with pcd-rs, read with pcd-rs
- [ ] Test interop: read a PCL-generated binary_compressed file correctly
- [ ] Test interop: verify pcd-rs output matches PCL's byte layout
      (decompress both and compare column order)
- [x] Test edge cases: empty file, single point, single field, large file

### Acceptance criteria

- [ ] A binary_compressed file generated by PCL is read correctly by pcd-rs
- [ ] A binary_compressed file generated by pcd-rs is readable by PCL
- [x] Existing binary_compressed round-trip tests still pass

## 1.2 Add I64/U64 types

PCL supports 64-bit integer fields (`I 8` and `U 8`). pcd-rs rejects them.

- [x] Add `ValueKind::I64` and `ValueKind::U64` variants
- [x] Add `Field::I64` and `Field::U64` variants to `DynRecord`
- [x] Update header parser to accept `(I, 8)` and `(U, 8)` in SIZE/TYPE
- [x] Update `read_chunk` and `read_line` for I64/U64
- [x] Update `write_chunk` and `write_line` for I64/U64
- [x] Update derive macros to support `i64` and `u64` field types
- [x] Add tests for reading/writing I64/U64 in all three data kinds

### Acceptance criteria

- [x] `i64` and `u64` fields work in both dynamic and static (derive) APIs
- [x] Round-trip tests pass for all data kinds (ascii, binary, binary_compressed)

## 1.3 Flexible header parsing

pcd-rs requires header entries in strict order (VERSION, FIELDS, SIZE, TYPE,
COUNT, WIDTH, HEIGHT, VIEWPOINT, POINTS, DATA). PCL accepts them in any order.
Many tools produce headers in different orders.

- [x] Refactor `load_meta` to parse header lines into a map, then validate
      required entries after all lines are read
- [x] Accept `COLUMNS` as alias for `FIELDS` (PCL compatibility)
- [x] Handle missing `COUNT` (default to 1 for each field, per PCL)
- [x] Handle missing `VIEWPOINT` for v0.7 (default to identity, per PCL)
- [x] Skip unknown header entries (warn, don't error)
- [ ] Validate WIDTH * HEIGHT == POINTS when all three are present
- [x] Add test fixtures with reordered headers
- [x] Add test for `COLUMNS` keyword
- [x] Add test for missing optional entries

### Acceptance criteria

- [x] Headers with entries in any order parse correctly
- [x] `COLUMNS` is accepted as alias for `FIELDS`
- [x] Missing `COUNT` and `VIEWPOINT` use sensible defaults
- [x] Unknown header entries do not cause errors
